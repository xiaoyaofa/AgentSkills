# 交付物格式契约（必须遵守）

> **为什么要有这份契约**：skill 的脚本管"算什么"，这份契约管"产出长什么样"。
> 没有它的时候，同一套流程换个板子/换个会话，产物形态就会漂 —— 实测漂到过：
> sheet 从 5 个变 6 个、**少了「器件清单」和「待确认问题」**、已用表**少了 muxmode 两列**
> （那是 BSP 最要用的），还混进了工具内部字段（`置信度`/`判据A命中页`）和
> skill 自身的验证结论。客户拿到的应该是**同一套骨架的交付物**。
>
> 这份契约由 `scripts/check_deliverable_consistency.py` 的 **[5] 格式契约**一节机器校验，
> 并有**可复制的骨架文件** [`pinmap-template.xlsx`](pinmap-template.xlsx)（5 个 sheet、只有表头）
> 作为形态基准 —— 导出前后用它比对，别凭这段文字自己"理解"。
>
> **★ 前置自检：`assets/` 或 `pinmap-template.xlsx` 不在 ⇒ 你手上是旧版 skill 的副本，先同步再动手。**

## 一、文件名

```
<板名>-引脚映射表.xlsx
<板名>-硬件资源分析.md
```

`<板名>` 取原理图上的板名（如 `ABC-1234`）。**不要**只叫 `引脚映射表.xlsx` —— 同一目录下会放多块板的产物。

## 二、xlsx：5 个 sheet，名字与列名按下面写死

sheet 的**顺序**也按此排列。

### sheet `0-说明`（2 列）
| 列 |
|---|
| `列 / 项` |
| `说明` |

内容是该表的**列语义与判读规则**（muxmode 怎么来的、引脚覆盖口径、查漏方法…）。**不是**诊断报告 —— sha256、连接器页号、判据 A/B 命中统计这类**过程信息不要放这里**（见「五、什么不该进交付物」）。

### sheet `1-底板已用信号`（10 列，顺序固定）
| # | 列名 | 说明 |
|---|---|---|
| 1 | `功能分类` | 调试串口 / 以太网 / SD/存储 / OSPI / USB / I2C / JTAG / 启动模式 / 按键 / 复位 / LED / 扩展 / 电源 |
| 2 | `原理图网络` | 原理图上的网络名 |
| 3 | `核心板引脚` | 核心板连接器脚位（数字或 L 系列） |
| 4 | `SoC ball` | BGA 焊球号 |
| 5 | `引脚原名 (Function0)` | 厂商引脚表 Function0 列 |
| 6 | `底板所需功能 (muxmode)` | ★ BSP 最需要的一列：目标功能 + muxmode；同名则写"（Function0，无需复用）" |
| 7 | `电平` | IO 电压域 |
| 8 | `原理图页` | |
| 9 | `负载 / 目标` | 接去了哪个器件/网络 |
| 10 | `备注` | |

### sheet `2-未使用信号`（7 列）
`核心板引脚`、`引脚表信号名`、`SoC ball`、`引脚原名 (Function0)`、`可复用为 (GPIO 等)`、`电平`、`备注`

> 该板若"未使用 0 只"，**保留这张表并只留表头**，不要删表、也不要拿它当过程记录表用。

### sheet `3-器件清单`（5 列）
`位号`、`型号`、`类别`、`原理图页`、`说明`

收录范围见 SKILL.md「逐页器件清单」一节的约定（功能性器件；成组小器件按区间位号；无源小件不逐颗收录）。

### sheet `4-待确认问题`（4 列）
`序号`、`待确认问题`、`影响`、`结论（客户确认后填）`

## 三、md：必备章节

标题里含下列关键词即可（编号可不同），但**都要有**：

| # | 章节关键词 | 内容要点 |
|---|---|---|
| 0 | 头部元信息块 | 板名/版本、原理图文件名、核心板型号、引脚表文件名、**本次走的哪条提取路线**（poppler `-layout` / pypdfium2「阅读序」）、分析日期、硬件状态（是否投板） |
| 1 | 概览 | 一句话说清这板子是什么 |
| 2 | 顶层框图 | 电源链路 + 核心板外设连线 |
| 3 | 逐页器件清单 | **含收录范围与位号↔型号置信度说明** |
| 4 | 外设与总线映射 | BSP 视角：功能 → SoC 节点 → 关键连接 → 备注 |
| 5 | SoC 信号使用与空闲 | 已用/未用数量 + 最有价值的未用组 |
| 6 | 电源与复位 | 电源域表 + 上电顺序 + 复位说明 |
| 7 | 与…差异（含「必须换 mux mode 的引脚」小节） | 与厂商现有板级 dts 的差异清单 |
| 8 | 待确认问题 | 需客户/硬件确认项 |

md 骨架模板见 [`report-template.md`](report-template.md)，直接照着填。

## 四、过程记录放哪

工具内部字段、判据命中统计、skill 自身的验证结论、产物路径清单 —— 这些**有保留价值，但不属于交付物**。要留就另存一个文件，**别用上面两个文件名**，例如：

```
<板名>-过程记录.md        # 判据 A/B 命中情况、[E]/[F] 按组裁决、--audit 盲区、验证结论
```

## 五、什么不该进交付物

| 不该出现 | 为什么 | 该放哪 |
|---|---|---|
| `置信度`、`判据A命中页`、`audit 命中数`、`[E]/[F]` 计数 | 工具内部字段，对读表的人没有意义，还占掉列位 | 过程记录 |
| ↑ 注意区分：这里禁的是 `pin_usage.py` 那个 **A/B 判据置信度列**；md §3 与 `0-说明` 里**要求**写的「位号↔型号 的置信度说明」是另一回事，别一起删了 | —— | —— |
| sha256、连接器页号、页脚正则、`--conn-page` 之类的命令参数 | 过程信息 | 过程记录 / `0-说明`页只留"列语义" |
| "Windows 通用性验证结论""建议反馈到 Skill""产物清单 `D:\...`" | 那是 **skill 验证报告**的内容，不是客户要的硬件分析 | 单独的验证报告 |
| 未标注置信度的器件型号 | 型号可能错配，交付前必须读图定案 | —— |

## 六、自检

```bash
python3 scripts/check_deliverable_consistency.py \
        --xlsx <板名>-引脚映射表.xlsx --md <板名>-硬件资源分析.md
# [5] 格式契约 一节会逐项核对 sheet 名/列名/章节；
# 表结构有意不同时用 --no-format-check 关掉。
```
